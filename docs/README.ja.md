# commit-with-fx

`fcom` はカレント Git リポジトリの変更を [fx](https://fx.sh/) で内容ごとに分類し、複数のコミットを作成します。Python 3、Git、fx が必要です。追加の Python パッケージは不要です。[English](../README.md)

## 導入

```sh
# このリポジトリを PATH に加える
chmod +x fcom fcom-config
export PATH="/path/to/commit-with-fx:$PATH"
```

## 使用方法

```sh
fcom                    # 現在のリポジトリの変更を分類してコミット
fcom-config all         # 既定: ステージ済み・未ステージ・未追跡を対象
fcom-config staged      # このリポジトリではステージ済みだけを対象
```

`fcom-config` はローカル Git 設定 `fcom.scope` を変更します。Git の無視設定に入っているファイルは対象外です。fx への依頼は１回で、差分を送信します。実行前に機密情報が含まれていないか確認してください。fx がコミット案を生成している間は読み込み表示が出ます。

コミット前に各コミット名と対象ファイル（追加・削除行数。バイナリは `binary`）だけを表示し、確認を**一度だけ**求めます。差分本文は表示しません。コミット名は `feat: ...`、`docs: ...`、`feat(cli): ...` などの Conventional Commits 形式です。`y` で実行、`n` で中止、`{"1":"fix: 新しい名前","2":"docs: 別の名前"}` で名前を修正して実行します。再確認はありません。fx の名前が規則に合わなければコミット前に停止し、修正入力が不正なら中止します。

変更のまとまり（Git の diff hunk）ごとに分割するため、同じファイル内の離れた変更も別コミットにできます。分割できない場合や fx が失敗した場合は確認前に停止します。承認までは元のステージ状態を変更しません。承認後は一時インデックスで順にコミットし、完了後に元のインデックスを最終コミットへ合わせます。Git フックも実行されます。**途中でフックや Git コマンドが失敗した場合、作成済みのコミットは残ります。** 残りの変更は `git status` で確認してください。`all` モードでは作業ツリーの最終状態を対象とします。ステージ済み変更が作業ツリーで完全に取り消されている場合は、黙って除外せず停止します。ステージ上の内容だけをコミットしたい場合は `staged` モードを使ってください。

テスト: `python3 -m unittest discover -s tests -v`
